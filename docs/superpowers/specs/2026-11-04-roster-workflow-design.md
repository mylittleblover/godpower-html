# 名单管理收尾设计

承接用户已授权的设置名单UI重做，3.0.71头像/性能版已单独提交并上传，后续在3.0.72工作版本推进，不覆盖已发布包。

目标：在设置当前存档内完成学生新增、直接分组、小组新增/改名/改色、成员选择与头像管理。保留原稳定UID、分数、库存、历史与事务保存，不恢复文本覆盖成员。

选择现行原生HTML+SaveManager.edit，在SaveRoster补小组增改及学生新增时可选分组；不调用旧DOM表单模拟点击、不另建权威名单。另两种方案（嵌入旧组菜单、重写整个名单服务）分别增加跳转或数据风险，均不采用。这是本次执行者按用户“自主推进”选定的实现。

界面为两个对齐的设置分区：左侧学生，右侧小组。每区顶部搜索；学生新增时可直接选择小组，编辑模式有取消。小组有紧凑新增/编辑表单，成员编辑在小组区内展开，避免滚到全页底部。复用既有头像选择器及tokens；没有新增永久工具栏或改变比赛卡片布局。

错误显示在工作区，等待事务ACK后清空表单；保存失败保留输入。切档清除旧表单/成员编辑上下文。搜索只过滤现有行，不重建输入。大量名单后续另做虚拟化，不在本次无证据引入复杂缓存。

验收：旧数据与两组分数/库存不变，新增学生一次命令分组、组新增/改名后刷新一致、编辑取消不写入、搜索不丢焦点、头像入口保留、成员不重复归属、1920×1080截图及14组布局不变。Windows真机仍NOT TESTED。
