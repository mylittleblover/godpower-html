# 《上帝的力量》V3 竞技规则系统详细设计规格

> 日期：2026-10-20；状态：**完整推荐设计，待用户总审**。本文件不是代码实施授权。配套总架构：`2026-10-19-godpower-v3-architecture-design.md`。
>
> 标签：**[确认]** 用户明确要求；**[推荐定稿]** 本次补齐的可实施默认规则，仍待总审；**[需旧版核验]** 现有 26 道具/All in/积分机制的具体实现需由 Codex 只读提取，禁止猜测或覆盖。

## 1. 目标与不可变约束

- [确认] 支持小组与个人竞技模式；学生实体独立于小组，个人荣誉不自动分摊小组积分。
- [确认] 26 个旧道具及既有语义保留，仅明确要求的变更才追加；七种状态、四项道具扩展见下文。
- [确认] 每隔 4～8 个有效回合触发随机事件；**事件全自动选择、执行和展示，无确认、选择、领奖、人工判定环节**。
- [确认] 下课结算不清空赛季积分/库存；封神榜结算归档赛季并重置赛季竞技进度。
- [推荐定稿] 竞技规则只存在于 Domain，所有操作经命令总线、原子事务、可审计日志；动画绝不作为生效条件。

## 2. 基础定义与事件时序

- **参赛单位 Participant**：小组模式为 GroupId，个人模式为 StudentId；所有道具/状态/事件统一引用 ParticipantId + mode + seasonId。禁止依名称识别。
- **有效答题回合**：一次被教师正式提交且成功结算的答题结果（含正确、错误、零分及 All in），全局回合计数 +1；预览、撤销、跳题、点名、单独使用道具、事件、自动重试不计回合。取消中的答题不计回合。一次多目标答题批次以一个唯一 `roundId` 计一次；批次内全部提交完毕后才计数。
- **回合结束顺序**：[1] 锁定题目/目标和输入 [2] 校验命令 [3] 计算基础答题得失 [4] 应用已有道具与状态的答题修正 [5] 应用活跃事件修正 [6] 提交积分与状态消耗 [7] 递减此前已生效的限时事件持续回合、到期移除 [8] 递增有效回合数 [9] 若到触发点则抽取并执行新事件 [10] 一次提交事务并发布结果供 UI 播放。新触发的事件**不影响刚结束的回合**。
- **持续 N 回合**：从事件发生后的下一次有效答题回合开始计算，经过 N 次全局有效答题回合结束后到期；不按每个参赛者答题次数分别计数。即使答题目标不是受益者，回合也计数。临时状态若注明“目标答题次数”则仅在目标答题完成时消耗。
- **目标锁定**：触发时确定所有事件受益/受害 ParticipantId；中途排名变化不改变对象。被移除的目标不重定向；效果自动失效并记日志。
- **跨课堂**：随机事件持续效果默认在下课时结束；可由教师跨课堂策略针对 `event_modifier` 类别覆盖。封神榜总是清除赛季临时事件。事件倒计时只在正式答题回合推进。

## 3. 积分计算和取整

### 3.1 通用规则 [推荐定稿]

- 积分始终是整数，允许负分；展示层不得自行取整。正向答题基础积分 `baseGain=max(0,rawAnswerDelta)`；负向答题损失 `baseLoss=min(0,rawAnswerDelta)`。
- **基础分倍数**（如双倍狂欢、后来居上）只作用于 `baseGain`，相互叠加时相乘；倍率计算结果统一在此阶段**向下取整**。
- **固定正确答题奖励**（黄金时刻、王者挑战、追赶之星）在基础倍数后加总；只在 `isCorrect=true` 时生效。多个不同来源可累加。
- **无敌/巨大化**的额外 25%～50% [确认：额外增加的比例]：对**经过基础倍率及固定奖励后的正向答题收益**分别计算，抽取整数百分比 25～50（含端点），每个效果各自向下取整后相加；不会把额外收益再次计入另一效果的基数，避免指数叠加。若答题结果非正，则额外奖励为零。
- 负分/零分不享受正向倍率；随机即时加减分不属于答题收益，不受上述倍率或无敌/巨大化加成。
- **冻结**：本次目标答题正向最终收益最多 1 分；如原本负分则保留负分；固定奖励和倍率也受上限限制。**麻痹**若命中“取消本次得失”，则本次答题的积分变化设为 0（含倍率和额外奖励），但答题事实、统计与状态持续次数照常记录。灼烧、中毒的答题后扣分属于独立后置伤害，不被麻痹抵消（可被现有明确免疫规则阻挡）。
- **后置状态扣分**：中毒固定 -2，灼烧从 1/2/3 中等概率抽取并扣分；多来源分别记账。最终积分变动 `answerDelta + postAnswerStatusDelta`。不设积分下限。
- **回旋镖花**：目标当前积分 `s`，扣除 `floor(max(s,0)/5)`；零分/负分扣 0，不会使负分者反获奖励。先读取扣分前当前积分再结算，同事务多次命中按命令序列依次计算。
- **All in**：保留旧版的押注、得失与结算公式 [需旧版核验]；冻结、麻痹禁止发起 All in，校验在扣押/结算前执行。事件奖励不会自动变为 All in 押注额。禁止凭空定义新 All in 倍率。

### 3.2 示例（验证规则而非旧版事实）

正确答题基础 +10；双倍狂欢 ×2；黄金时刻 +3；无敌抽到 25%，巨大化抽到 50%：正向收益 23；无敌额外 `floor(23×.25)=5`；巨大化额外 `floor(23×.5)=11`；答题共 +39。若冻结生效则答题收益上限为 +1；若再中毒，则总变化 -1。

## 4. 七种状态的完整生命周期

| 状态   | 触发及作用                                               | 默认持续                                                | 重复施加                       | 互斥/特殊规则                                                         |
| ------ | -------------------------------------------------------- | ------------------------------------------------------- | ------------------------------ | --------------------------------------------------------------------- |
| 灼烧   | 目标每次答题结算后随机 -1～-3                            | 目标接下来 2 次答题                                     | 不叠伤害；刷新为剩余次数较大值 | 可净化；不会触发额外回合                                              |
| 冰冻   | 阻止一次道具使用；禁止 All in；正向答题收益至多 +1       | 目标接下来 2 次答题或成功阻挡一次道具后解除（先到为准） | 刷新次数；不堆叠阻挡次数       | 尝试使用道具时阻挡并消耗冰冻，原道具不消耗；该尝试不计有效回合        |
| 麻痹   | 禁止 All in；目标每次答题有 50% 概率取消该次答题积分得失 | 目标接下来 2 次答题                                     | 刷新次数                       | 只取消答题得失，不取消后置毒/灼烧                                     |
| 中毒   | 每次目标答题结算后 -2                                    | 目标接下来 3 次答题                                     | 刷新次数，不叠伤害             | 可净化                                                                |
| 眩晕   | 使用可定向攻击道具时 50% 概率将目标改为自己              | 接下来 2 次符合条件的道具使用尝试                       | 刷新次数                       | 非定向/全局道具不触发；自伤不合法时使用失败且不消耗道具               |
| 无敌   | 答题后额外 +25%～50% 正向积分，保留旧有效果              | 目标接下来 2 次答题                                     | 刷新次数                       | **旧版无敌的防御/免疫效果必须先核验并保留**；额外奖励规则不替代旧效果 |
| 巨大化 | 答题后额外 +25%～50% 正向积分，保留旧有效果              | 目标接下来 2 次答题                                     | 刷新次数                       | **旧版巨大化的其他效果必须先核验并保留**                              |

- 所有持续次数为 [推荐定稿] 默认值，教师可通过规则配置更改，但不能改变已确认的基础效果语义。
- 同一状态不叠层，不同状态可并存；同一事务多次施加时按最大剩余次数合并。净化仅清除标记 `cleansable=true` 的负面状态，不能清除永久荣誉、赛季成就或积分。
- **负面状态随机池**：灼烧、冰冻、麻痹、中毒、眩晕；**正面状态池**：无敌、巨大化。魔法风暴只从负面池抽取，避免“负面事件给无敌”的歧义。
- 旧道具具有免疫、反弹、清除或保护效果时，**旧版规则优先**；若冲突不可判定，Codex 应列为差异项等待审查，不能静默删除旧效果。

**抽取规则**：类别概率积分25%、道具25%、状态20%、逆转20%、特殊10%；类别内按上表相对权重抽取。先剔除不合法候选，再对剩余类别概率重新归一化；若无合法事件，则本次记 `noEligibleEvent`，并重新抽取 4～8 回合间隔。每次成功触发后同一事件禁止紧接着再触发；即时大范围事件 EV05/EV09 额外冷却 2 次成功事件。不能用“抽到不合法就让教师选择”的流程。

**自动条件**：

- EV07 无“稀有道具”定义或后半区无人有空位时不合法；不允许为实现此事件临时杜撰旧道具稀有度。
- EV08 没有可替换且有合法替代道具时不合法；替换后保持库存数量不变。
- EV09 参赛者至少 2 名；人数 2 时选 2 人，人数 3 以上均匀选 2～3 人。
- EV10 与 EV12 不可同时生效；抽取前排除冲突候选。
- EV13 排名按触发时总分降序、稳定 ParticipantId 升序确定，后半区取 `ceil(N/2)` 名；至少 2 人。
- EV14 第一名若并列，所有并列第一均视为领先者、不享受奖励；若全部并列第一则事件不合法。
- EV15 最末位并列者中随机选 1 人；至少 2 人。
- EV16 至少 2 人各有可交换道具，库存容量不变；原道具绑定规则必须允许转移。
- EV12 只在至少有 2 个合法攻击目标时才可改变目标；若重选失败则维持原目标。

## 7. 随机源、事件生命周期与撤销

- 赛季保存独立的确定性 PRNG 状态/种子；每个抽取步骤（触发间隔、类别、事件、目标、数值、道具、状态）记录抽取结果和 PRNG 状态变化。重放只消费已记录结果，不重新抽奖。
- 初始开课时抽取下一次间隔 4～8（含端点，等概率）；仅在事件已完成或被记录为无合法候选后重新抽取。禁用事件系统时暂停倒计时而非暗中触发。
- 全部事件由 `ResolveRandomEvent` 应用命令处理，成功后原子提交：效果、持续时间、库存、分数、历史、PRNG 状态、下一触发点；UI 异步展示动画，失败只降级为文字通知。
- 事件效果与触发它的答题回合属于同一个逻辑提交单元；撤销该答题应撤销相应事件与 PRNG 变化，再次执行相同操作得到相同抽取结果。撤销不触发额外事件。跨课堂/封神榜归档之后禁止直接跨边界撤销。
- 教师仅在设置中启停事件池、修改类别/单事件权重、调整持续回合等；事件发生时不得出现需人工确认的操作。课中修改配置仅对下一次事件抽取生效，已生效的持续效果按原快照执行。

## 8. 结算、荣誉与排行榜统计

- 下课结算按课堂会话事件日志聚合，不修改赛季积分/道具；封神榜先生成不可变赛季快照、验证持久化成功，再创建新赛季，绝不先清空。
- `最高正向得分`：本课堂所有正向积分流水之和（负向流水不抵消）；`排名上升最多`：课堂开始与结束时同一参赛者的名次差，名次并列采用竞赛排名法（1,1,3）；`道具使用最多`：成功消耗并执行的道具数量；`承受道具效果最多`：收到并实际生效的敌对道具效果次数，免疫不计；`All in 失败`：依据旧版 All in 判定记录次数，不按结果分数猜测。
- 每项可多人并列，结算 UI 全部展示并列者；无有效数据时显示“本节无记录”，不强行选冠军。被撤销的流水不参与统计。
- 学生个人荣誉只能来自具名 StudentId 的可归属动作；小组加分和小组道具自动事件不得平均分给学生。永久荣誉不因封神榜重置。

## 9. 首页阶段与积分视觉

- [确认] 最高参赛小组分数阶段：1～49；50～499；500～4,999；5,000～99,999；100,000～9,999,999；10,000,000 及以上。
- [推荐定稿] 最高分 ≤0 时使用第 1 阶段的音乐与最低视觉级别；个人模式按最高参赛者分数计算。空教室使用默认首页，不启动阶段音乐。阶段切换以当前赛季总分为准；不跨赛季继承。
- 积分动效四类：基础答题、道具即时变化、状态后置修正、随机事件奖励/扣除；合并展示净变化，同时保留可展开的来源明细。动效可关闭/减少动态效果；动效播放失败不影响积分事务。

## 10. 竞技规则引擎接口（建议）

```ts
type ParticipantId = string;
type RoundId = string;
type SeasonId = string;
type SourceKind = "answer" | "item" | "status" | "random_event" | "settlement";
interface RuleContext {
  seasonId: SeasonId;
  mode: "group" | "individual";
  roundId?: RoundId;
  rng: DeterministicRandom;
}
interface ScoreLine {
  participantId: ParticipantId;
  amount: number;
  source: SourceKind;
  sourceId: string;
}
interface RuleResolution {
  scoreLines: ScoreLine[];
  stateChanges: unknown[];
  historyEntries: unknown[];
  rngAfter: unknown;
}
interface RandomEventDefinition {
  id: string;
  category: string;
  eligible(ctx: RuleContext): boolean;
  resolve(ctx: RuleContext): RuleResolution;
}
```

插件只能通过权限网关请求受控命令或注册经过校验的事件定义，不得自行更改权威状态、随机种子、结算流水或历史记录。自定义事件不得引入强制人工交互。

## 12. Codex 实施交接与阶段门槛

1. **只读盘点**：读取最新 `godpower-electron` 及其共享核心依赖，列出 26 道具、旧 All in、旧状态、积分处理、存储/撤销、比赛回合统计的真实行为与源码路径；产出 `legacy-item-baseline.md` 和差异表。
2. **设计对齐**：将旧版已存在且未明确更改的语义补入本规格；如与推荐默认冲突，以“保留旧版”为优先，提交差异供设计评审，不得暗改。
3. **实施计划**：拆为基础规则/状态/事件引擎/道具扩展/结算统计/UI 演出/回归测试等独立任务，列明具体文件和测试。
4. **审批后实施**：在用户审阅本规格及实施计划前，不执行大规模代码改动。实施后须跑自动测试、Electron 实测及 14 组布局验收。

**本次补齐内容的边界**：16 种事件、持续时间、概率、取整、冲突、统计口径等均为可实施的**推荐默认规则**，不等同于用户逐项确认；旧版 26 道具细节必须先核验，不能编造。
