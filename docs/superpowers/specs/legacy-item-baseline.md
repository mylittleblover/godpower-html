## Current item semantics (default configuration)

Rounding in `src/script/00.js`: quarter/third/half damage uses `Math.round(value / denominator)`; non-negative eligibility is `score >= 0`. Item score changes pass through configured per-item score multipliers and shared `applyItemScore`/defense flow. These formulas are historical behavior, not the new competition specification.

All 26 draw counts are configurable except some fixed-duration status item charges (`mega`, `power`, `boo`); each group inventory is normalized to at most three unique keys, with primary slot index 0 and secondary slots 1–2. Exhaustion removes the entry, allowing queued items to promote. `itemInstanceId`, configured charges, acquired timestamp, item-use lock and triple continuation are part of stored identity/state.

## State and asynchronous defense details

The code stores a mix of item state: `itemEffect.type` with `hitsLeft`/`roundsLeft`/`startedAt`, `featherDodge`, `iceLock`, `iceRoundsLeftV218`, `booShield`, `booRoundsLeftV218`, `itemUsedThisRound`, and `roundItemContinuationKeyV218`. Star/Mega defenses reduce `hitsLeft`; a passive attack block is not the same as an item attack landing. A pending spiny defense waits for confirmation, then revalidates classroom/group/item identity before consuming or continuing. Achievement/event rules must observe the committed result after that branch, not the prompt, click, or animation.

## Existing behavior that must not be overwritten by recommendations

1. The 26 key set and defaults above are the legacy baseline. New rarity, exchangeability, event compatibility, or inventory restrictions are not defined in the current domain catalog.
2. Existing All In formula is exactly current score ×2 on correct and 0 on wrong, with integer-safety rejection. No new freeze/paralysis behavior exists.
3. Current `pkTotal` increments once per successful formal `judgeRound`; picker, item use and failed/retried commands are not formal answer rounds.
4. Ordinary next round retains season scores and inventory. Final Hall of Fame archive and clearing are a separate operation.
5. Random behavior cannot currently be replayed from storage because `Math.random` state is not captured.
6. Current game has group mode. An individual participant model is not present; student membership is an array of names and is not a stable StudentId entity.
7. No random event pool, seven-state engine, session-end settlement log, or competition event engine exists in the current implementation.
