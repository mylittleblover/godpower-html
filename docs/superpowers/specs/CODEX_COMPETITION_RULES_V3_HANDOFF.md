# Codex 交接提示词：竞技规则 V3.0

请先阅读：

- `docs/superpowers/specs/2026-10-19-godpower-v3-architecture-design.md`
- `docs/superpowers/specs/2026-10-20-godpower-v3-competition-rules-design.md`

本轮仅做**只读仓库核查、差异分析和实施计划**，不得直接重写竞技引擎或删除旧功能。

1. 确认 `mylittleblover/godpower-electron` 最新分支、HEAD 和共享核心来源。
2. 从实际源码逐一提取现有 26 道具、All in、积分、免疫、反弹、库存、撤销、状态与回合计数规则，生成 `legacy-item-baseline.md`，标注路径与关键函数。
3. 对照 V3.0 设计规格，生成差异矩阵：旧版需保留、用户明确新增、推荐默认、冲突需裁定。不能以推荐规则覆盖未知旧规则。
4. 为 16 个全自动事件、七状态、四项道具扩展、结算、确定性随机源设计可测试接口和迁移顺序。
5. 制定逐文件实施计划、红绿测试、兼容迁移、回滚方案和 Electron 人工验收清单。
6. 输出发现的问题和建议，等待用户审阅设计与计划后再编码。

硬约束：随机事件不要求任何教师/学生手动操作；不得破坏 14 组布局、26 道具既有功能、封神榜和课堂结算的不同生命周期；动画不得控制数据生效；插件不得直接改写核心状态。
