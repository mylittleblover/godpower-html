## Unresolved decisions exposed by the comparison

1. The supplied document marks the scoring formula, event interval/weights, several effect durations, and event effect details as [Recommended default] and says they are not user-approved. A formal approval is required before those become game rules.
2. Legacy item score rounding is `Math.round`; new examples use `floor` for multipliers/bonuses. A compatibility rule is needed for which transformations use old versus new rounding.
3. Kamek and Item Box exceed the current 26-key catalog. Confirm whether they are new obtainable items, event-only items, or design placeholders; define their stable keys and images before schema work.
4. Existing Star/Mega already block three attacks and carry overtake suppression. New extra score bonuses and duration rules must coexist without deleting those properties.
5. Current Freeze only applies to item use and duration decay; proposed Freeze also limits positive answer score and blocks All In.
6. Current normal score permits negative totals, while item targeting often excludes negative score. New all-score/event rules need a per-operation eligibility table.
7. Current actual rank sort preserves stable order for ties. New event selection asks stable ParticipantId ordering and contest-rank display. The exact event tie-selection rule must not silently redefine ordinary UI ranking.
8. Member names are not stable student identities. Individual mode cannot safely persist data or personal honors until an import/rename/delete policy for StudentId is approved.
9. Proposed random event effects/weighted categories have no rarity mapping for all 26 items and no deterministic PRNG repository yet.
10. The required companion architecture spec `2026-10-19-godpower-v3-architecture-design.md` was referenced but not included in the provided ZIP and is absent from both worktrees.
