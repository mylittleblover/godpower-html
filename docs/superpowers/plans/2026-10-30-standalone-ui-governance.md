# 无插件过渡版 UI / CSS / JS 治理执行方案

本方案替代 2026-10-20 UI 治理与插件平台计划在当前过渡分支上的执行效力。旧规格保留为历史记录，不再按其插件阶段推进。用户已授权更新方案并直接实施，不再设审批关卡。

## 基线与边界

HTML 基线 990558219f79a5b92d93a6bc455a91bf75310328（3.0.57），Electron 基线 a6ed18a。普通功能弹窗使用主页面原 DOM；独立窗口仅承担点名与全屏表现等既有职责。不恢复 detached dialog transport。

保留：无插件运行、11种内置可配置主页卡片、课程资源入口、两主题、26道具、已有成就、头像、六槽自由赋分、自定义多音效、独立BGM音量、浅色小组编号与分数样式、悬浮窗位置跟随和指针拖动、后台运行。不得改变权威存储、历史语义、规则或14组几何。已有未跟踪产物不纳入提交。

仅 Chromium 1920×1080 1x。禁止 CircleCI 操作。Windows系统键盘、实体触屏及多显示器未实际测试时保持 NOT TESTED。

## 职责

- Domain / Application：比赛规则、验证、命令、事务、历史；UI不重复实现。
- UI Shell：导航、页面注册、生命周期、焦点；内部registry不扩展为插件平台。
- Presenter：只读展示投影；DOM adapter负责局部更新。
- Motion：入场、退出、取消、减少动态效果；不决定业务结果。
- CSS：tokens → 基础控件 → 页面/组件 → 有明确原因的兼容层；先验证层叠结果再删除。
- Electron：安全preload、窗口位置/尺寸/后台运行与表现通信；不克隆普通弹窗。

## 分批执行与提交边界

1. G1 生命周期：审查 DisposableScope、监听器、timer/observer归属；补失败用例并修复清理缺陷。退出条件：清理幂等、一次性监听器及时释放、捕获阶段正确移除；页面生命周期及内部弹窗浏览器回归。
2. G2 设置与窗口：按设置分类、输入、确认、音频拆owner；先记录现有刷新路径，仅替换证明会重建无关输入的路径。验收输入节点/焦点、立即保存、重入/退出动画、无页面reload；不更改现有入口与样式。
3. G3 比赛展示：梳理唯一 render owner、得分/排名/道具投影和动画租约；每次只迁移一个刷新域。相同fixture比较14组几何，保留攻击/FLIP时序，不把异步行为改为同步。
4. G4 CSS：重新生成当前selector/source/order/media ownership，按组件逐块验证。比较两主题computed style和截图，保留特殊状态/关键帧；重复选择器只是候选，不按计数删除。
5. G5 Electron同步发布：每批HTML稳定后记录源SHA与SHA256，再同步Electron；验证窄IPC、点名、特效、后台与输入。正式版本同时更新可见/内部版本；未完成的阶段不伪装为发行版。

每批：失败测试→最小实现→相关单测/浏览器→报告→独立提交。无需每批全量截图；布局/外观改变必须真实截图。只在实现相应领域时扩大测试范围。发布仍需构建、自包含校验及必要跨模块回归。
