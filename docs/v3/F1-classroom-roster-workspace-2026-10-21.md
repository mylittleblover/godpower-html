# F1 本地教师与课堂名单工作区

版本：3.0.41
范围：HTML 源码；只使用 Chromium 1920×1080 @1x 验收。

## 决策

- 教师档案是本地工作区标识，不是登录认证、云账号或同步身份。
- 课堂名单可以独立编辑，但不会自动改写正式比赛中的小组和成员。
- 比赛状态仍以 `godpower_state_v2` 为准，名单文档独立保存在 `godpower_classroom_roster_v1`。
- 从当前比赛创建名单副本只读取小组/成员并生成稳定身份；源比赛分数、回合、历史和成员数组不变。
- 同名学生保留为不同 `studentUid`。个人参与模式不强制分配小组。
- 名单备份采用 `godpower-classroom-roster-backup` v1 容器，包含名单文档和头像资源元数据/Base64 字节；兼容导入旧版纯名单 JSON。
- 名单导入先完成 JSON/schema、头像类型/签名、引用完整性、大小与 SHA-256 校验，再由资源仓库批量写入、名单仓库 CAS 写入及回读验证；名单提交失败会补偿删除本次新建头像，不删除既有资源。
- 名单应用只更新权威比赛中稳定 `groupUid` 对应的 `members` 数组，不增删或重排小组，不更改分数、道具、回合与规则字段。
- 应用前必须保存本地名单，先展示每个小组的当前/目标成员和增删改结果，再进行危险操作确认；保存成功后显示可撤销的历史操作。
- 比赛状态通过统一 `runClassroomCommand` 完成快照、历史、持久化和回滚；只有权威存档返回持久化成功才报告应用完成。名单仓库只读，不存在 roster/classroom 双键写入。
- 预览失效条件包括比赛对象/状态、赛季、名单 profile/classroom、仓库 revision 或原始存储字节变化；确认前及事务内再次校验，陈旧确认拒绝。
- 同一小组允许同名学生保持为独立列表项。点名防重复键采用组内位置，旧版 `${groupId}__${memberName}` 键在迁移期间仍可被识别。
- 学生头像仅接受经签名验证的 PNG/JPEG/WebP，大小不超过 2 MiB；二进制复用既有离线资源库，名单只保存 `avatarResourceId`。替换/清除只解除旧引用，不主动删除文件，以免删除其它引用或备份需要的资源。
- 如果写名单时失败，新上传的未引用资源会补偿删除；已存在并复用的资源不会被删除。头像读取只显示本课堂内、标记为 `student-avatar` 的图像，并在重绘时撤销 Blob URL。
- 更换/清除头像后旧资源仍保留；在完成全局引用扫描前不做自动清理，以免删除仍被其他课堂或备份引用的资源。profile 级偏好隔离仍待后续迁移。

## 已实现

- 设置页“学生与小组管理”新增本地名单工作区。
- 教师档案和多个课堂的选择、新建。
- 从当前比赛创建独立副本。
- 学生新增、删除、改名，以及按 profile 独立设置分组。
- 小组参与与个人参与模式。
- 全文 JSON 导入；导出版本化名单/头像组合 JSON 备份，兼容导入旧名单 JSON。
- 组合备份对单头像和总量设大小上限；校验损坏字节、缺失/多余引用、跨课堂关系与 SHA-256。
- 导入时复用完全匹配的头像；resourceId 冲突时创建新 ID 并重映射名单，不覆盖已有 Blob。
- 名单提交失败会回滚本次导入新建的头像，保留原名单字节。
- 通用资源库删除前读取最新名单；引用中的头像和名单不可读时拒绝删除，解除引用后仍可显式确认删除。
- 导入错误保留此前已保存的名单；比赛权威数据不变。
- CAS 版本冲突、写后读回与回滚仍由 `ClassroomRosterRepository` 负责。
- 预览并按稳定小组 ID 应用成员名单，保持比赛的分数/道具/回合数据不变。
- 应用操作加入既有历史并可撤销；主存档写入失败精确回滚内存比赛状态及历史。
- 刷新后恢复应用结果；名单仓库字节不被应用流程修改。

## 自动化证据

`tests/e2e/classroom-roster-workspace.mjs` 实际启动 Chromium，在 1920×1080 下验证：

- 14 组、28 名学生的副本创建。
- 改名与分组保存。
- 两个教师档案的分组分离。
- 创建第二个课堂并保存个人参与模式。
- JSON 导出下载。
- 损坏导入拒绝且仓库字节保持不变。
- 操作前后权威比赛小组与回合状态序列化完全相等。
- 工作区不产生水平溢出；截图保存在 `artifacts/f1-roster-workspace/1920x1080.png`。

`tests/e2e/roster-competition-apply.mjs` 在同一视口另外覆盖：预览取消不改数据；存储主键写入抛出 `QuotaExceededError` 时，比赛对象、历史、权威原始字节及名单原始字节均不变；确认成功后分数/道具保持、成员改动可在刷新后恢复并可撤销；同一组重复姓名及顺序经规范化和刷新后保留；预览期间名单变更会使旧确认失效。预览截图为 `artifacts/f1-roster-workspace/apply-preview-1920x1080.png`。

头像回归同样使用 1920×1080 Chromium：上传 1px PNG 后验证 `avatarResourceId`、IndexedDB 资源内容与课堂作用域；在名单存储抛出 quota 错误时，新建资源回滚、原头像引用和已有资源保持；刷新后 blob 图片可读。头像截图为 `artifacts/f1-roster-workspace/avatars-1920x1080.png`。自 3.0.39 起，名单导出已包含当前课堂引用的头像文件字节，可作为单文件跨设备备份；未引用的孤立资源不包含在内。

3.0.40 对应构建单文件8,182,801 bytes，SHA-256 `acea4740cc6b274f6f60d588876f84ac78c5d9d7687ff1f4f34f5f2ec288c224`，Electron 3.0.40 同步验收见 `docs/validation/v3.0.40-electron-sync.md`。后续 3.0.41 的主存档恢复切片在 `docs/validation/v3.0.41-corrupt-snapshot-recovery.md` 独立记录；Chromium 仅测试1920×1080 @1x，Windows真机未测，无 CircleCI 操作。
