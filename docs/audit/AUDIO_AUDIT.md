# 按钮与自定义音效接入审查

2026-10-18，仅 Chromium。范围是音效接口、真实文件上传、播放路径和资源生命周期；不把自动化断言等同于真实听感验收。

## 实际清单

运行 `node scripts/audio-inventory.mjs` 可重建 `AUDIO_INVENTORY.json`。使用 Acorn 扫描 src 所有 JavaScript 的 playSound 调用，并和实际浏览器设置页生成的槽位核对。初版发现 42 个字面量调用位置、7 个动态调用位置；没有未知字面量槽位。

上一阶段活动自定义槽位共 41 个：11 个基础/抽签音效、4 个公共道具事件、26 个独立道具音效。浏览器逐槽验证上传入口并注入样本、调用播放路径；结果见 `artifacts/classroom-feedback/audio-slots.json`。这验证每个活动槽能使用自定义资源，并不表示逐一实际触发了所有 26 个道具的攻击、防御组合。

5 个旧通用别名 item_use / item_attack / item_buff / item_status / item_steal 被现有逐道具音效替代，继续抑制重复播放，保留旧资源和导入兼容。音乐轨道继续使用原独立音乐管理系统；本轮未逐轨耳听过门与循环。

## 确认并修复

- 按钮点选槽已有上传功能，但大量按钮没有调用。改为全局事件委托，动态按钮与键盘点击同样接入；保留业务音效，并对同一次点击的旧 ui_click 调用去重。
- 点击声可关闭和独立调音量，经过原主音量；自定义点击声采用单声部，避免长文件快速点击叠加。
- 默认 roll_loop 的试听没有合成分支，增加短刻度试听示例。实际抽取继续采用原连续循环缓冲，并未把运行声改成单次刻度。
- 文件读取完成后使用可变 currentUploadingSlot，存在串槽风险。读文件前捕获槽 ID。
- 原上传未等待事务完成便提示已保存。现在等待 IndexedDB complete，error/abort 明确提示未保存；旧磁盘资源保留。解码失败保留原可播放资源。

## 自动化与人工边界

`node tests/e2e/audio-customization.mjs` 实际执行 WAV 上传、IndexedDB 落盘、真实鼠标与 Space 点选、去重、关闭、主音量、并发读取、事务中止、损坏音频和默认试听。浏览器隔离存储，不触碰课堂数据。

真实课堂设备仍需人工执行（NOT TESTED）：

1. 从音效设置逐槽试听默认及自定义文件，记录音色、响度与削波；备用刻度按界面说明验收。
2. 快速点击、长点击文件、开关静音及调节主音量，耳听无叠音、静音确实无声。
3. 开始/停止抽取，确认循环声与停止声衔接；三模式各执行一次。
4. 开始答题、思考、结算，试听音乐过门、循环点和音量平衡。
5. 实际音箱、蓝牙/有线设备各记录设备型号、浏览器版本、输出音量和异常。

## 追加需求：同一操作的随机候选

41 个活动槽均增加多文件追加与候选管理。统一选择器覆盖普通音效、26 个独立道具及抽取循环。旧主音效键保持不变，候选另存；BIN 原索引保留结构并增加可选文件名。选择随机源使用 crypto，不消耗业务随机数；每次选择一份，循环开始选一次。测试 `multiple-audio.mjs` 验证实际上传、播放随机边界、26 道具与循环、真实刷新、BIN 往返、单项移除及还原事务失败。
