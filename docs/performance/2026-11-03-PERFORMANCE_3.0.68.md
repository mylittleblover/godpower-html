# V3.0.68 公共渲染与桌面保存治理

延续3.0.67，保护28道具、积分、点名算法、音效、头像、历史和14组布局。未关闭/缩短动画；不重置用户数据。

## 1. 弹窗观察器

原实现对body子树任何class/style/childList变化遍历16个窗口。100次无关小组样式变化造成1600次窗口查询。现在从mutation目标及添加/删除的子树确定受影响窗口；全局body可见性变化仍做完整协调；新增open属性观察，保留原生dialog生命周期。初始完整扫描保留。窗口内部内容替换、动态插入/删除、关闭按钮重建、焦点栈与Escape不删除。

原1600次查询/约2.2ms → 0次/约0.9–1ms（100次微任务样式更新）。此项绝对时间收益有限，不将查询下降当作整个程序恢复流畅的证明。

## 2. 隐藏欢迎页

DesktopUI.renderWelcome仍执行observeVisualState，以保持后台道具队列与效果事件；欢迎页DOM、每日内容、布局读取和副本检查只在当前页面为welcome时执行。重新进入时读取权威状态，无需复制一套业务缓存。时钟的3.0.67修复仍保留。当前viewport尺寸在初始化、resize与applyZoom更新，不能因为跳过隐藏欢迎页而失效。

先失败再通过的真实浏览器场景：14组，隐藏页100次名称更新；DOM变更1500→0，道具揭晓事件始终1次，进入后显示最终名称。五批每20次隐藏欢迎renderer的原始耗时约547–1440ms → 0–0.3ms；最终复跑包含14.1ms冷态批次，其余0.1–0.2ms。这里只衡量被消除的隐藏页面工作，不是全程序提速倍数。

顺序、无CPU采样器的同条件诊断（基线befcb81，即已包含弹窗治理）：renderAll同步中位数106.3→31.1ms，切页111.8→63ms；均为少量合成样本。网格仍有自己的成本，帧间隔有较大波动，不能宣称所有动画均已提速。

## 3. 全屏合成实验：没有保留推测性样式修改

诊断注入will-change分层、contain布局/绘制隔离，先后各两轮并穿插基线。后半轮基线与分层P50均约66.7ms，前半轮波动很大；收益不能与预热/主机波动区分。两项实验均未写入产品CSS，没有追加覆盖补丁。

SystemInfo实际报告：ANGLE SwiftShader，gpu_compositing=disabled_software、rasterization=disabled_software。当前环境不能验证Windows硬件透明合成效果。此前全屏低帧间隔只能证明软件渲染场景卡顿，不能代替Windows GPU根因结论。Windows全屏/投影/驱动性能仍NOT TESTED，PERF-067-02保持OPEN。

## 4. Electron磁盘保存（实现位于Electron仓库）

发现原save-file.write同步JSON序列化、writeFileSync、readFileSync校验和renameSync。即便IPC返回Promise，磁盘操作期间仍阻塞整个主进程，影响浮窗/全屏消息处理。

改为FIFO异步磁盘I/O，每项接受时固定目标路径及字节，逐项临时文件写入→完整读回校验→原子重命名。读取/改路径/重置先等待已接受队列；正常退出等待待写入完成。失败不替换旧文件，下一次写入仍能继续。JSON序列化仍在主线程、大存档尚有后续成本，不声称所有保存耗时已经消除。

同一真实临时磁盘、8次1MiB写入、baseline/after/after/baseline顺序：原事件循环最大间隔43.1/32.3ms→4.9/5.1ms；写入期间心跳0次→32/37次。总写完耗时原32–43ms，异步50–55ms；目标是使窗口消息可处理，不是声称磁盘吞吐提高。原子校验、顺序、队列失败恢复与路径捕获测试通过。
