# V3.0.67 第一轮公共路径修复

继续审计Windows Electron 3.0.64的全局卡顿。本轮产品修改仅两项，不改竞技、存档格式、布局及动画设计。

## 已修复

1. core/picker-bridge.js快照读取不再随机抽取特效样式。每个rolling业务通知选择一次，后续同轮快照复用；新轮仍随机。真实Chromium空闲100次读取：原93次payload变化→0次。去重恢复后主窗口不会仅因样式随机数不断发送gp:state/gp:shell。仍保留120ms状态检测以兼容原有状态更新，不声称完全消除轮询。
2. navigation-and-clock.js时钟继续更新头部和时间，但仅在欢迎页可见时调用欢迎页完整renderer。业务操作的renderWelcome/visual状态跟踪不改，不漏道具视觉事件。模拟100次隐藏时钟tick，欢迎renderer调用100→0；五批每批20tick的同步耗时中位数19.8ms→0.3ms。原始样本含38ms离群值，不把该微基准外推成全程序提升66倍；实际是消除每秒一次不必要隐藏刷新。

## 扩大审计

- 头像：groupDataUrl合成/缩略图有缓存，读取快照使用Cached接口，不是每次IPC都重新canvas编码。点名转轮仍每50/70ms replaceChildren，且同时有视觉转带；这是下一项需要测量/收敛的重复工作，尚未修改。
- 音频与资源：已检查对象URL创建/回收入口，多数具有回收；decodeAudioData分布在菜单、资源加载和设置导入。没有实测长时间自定义音频/头像压力，不能宣称无泄漏。
- 历史：快照深拷贝groups、itemGlobal和achievementLedger，历史持久化序列化最多40个完整快照。大型自定义图标/成员/长期成就数据可能放大成本；小样本saveState快不能排除此项，尚未用真实课堂文件测试。
- 原生窗口：所有角色backgroundThrottling:false；全屏CSS含透明背景取样、模糊与发光/粒子。Windows GPU、透明窗口合成、投影及缩放需原生诊断；当前Linux Chromium帧采样只能确认共享页面特效卡顿，不能冒充Windows桌面实测。
- 全量刷新、欢迎巡航副本重复检查和body子树弹窗扫描仍待处理，见前一份审计。不得为提速直接跳过业务视觉状态通知、焦点管理或保存。
